# Monster Roadtrip 번역 및 QA 기준

- 한글화 대상은 **3편 Monster Prom 3: Monster Roadtrip**, 1편/2편 자료는 조회 참고만 합니다.
- 원문 `work/source/`는 게임에서 읽기 전용으로 추출합니다. 원문 게임 파일을 바꾸지 않습니다.
- 원문 탭 구분 행의 **네 번째 필드(`index=3`) 텍스트만 번역**합니다.
  일반 `\t` 대사뿐 아니라 `>choice\t`, `>action\t`에서 네 번째 필드가
  사람이 읽는 선택지/행동 문구인 경우도 반드시 번역합니다. 그 외 이벤트
  헤더 `>>>`, 메타 지시문 `>event_type`, 화자·표정·배경·조건을 보존합니다.
- `%...%`, `[...]`, `<...>` 제어 토큰의 종류와 출현 횟수, 원문에 있는
  아라비아 숫자와 `+2`·`-1` 등 능력치 증감 표기를 정확히 유지합니다.
- 자연스럽고 문맥에 맞는 한국어로 욕설·성적/블랙코미디·메타 농담을 보존합니다.
  게임 코드나 구조 지시문을 일반 문장으로 착각해 번역하지 않습니다.
- 각각의 `translations/english_events_*.json`은 대응하는 원문 TextAsset의
  SHA256과 해당 텍스트 행 SHA256·물리 행 번호·이벤트 이름을 검증합니다.
- 번역을 완료하지 않은 대사는 일괄 자동 번역 또는 추정 문구를 넣지 않습니다.
- 원문 전체가 `...`처럼 말없는 반응인 경우에는 `……`를 허용합니다. 그 외
  일반 대사를 한글 없이 기호로만 대체하는 행위는 검증 단계에서 거부합니다.
- **완역 후 필수 조사 전수 QA:** 주인공 이름 빨강·노랑·초록·파랑은 모두 받침이
  있으므로 이름 바로 뒤에 `잖아`가 붙으면 `이잖아`로 교정합니다. `%CURRENTPLAYERNAME%`
  및 `%CURRENTPLAYERNAMECAPS%`도 실제 표시 이름을 기준으로 검수합니다.
  `가/는/를/랑/와`처럼 받침과 맞지 않는 조사는 원문 문맥 확인 후 각각
  `이/은/을/이랑/과`로 교정합니다. 다만 `알잖아` 같은 일반 서술어의 어미는
  절대 무조건 치환하지 않습니다. `python -X utf8 scripts/audit_protagonist_particles.py`
  는 수정하지 않고 의심 후보만 나열합니다. 최종적으로 조사 누락과 스탯 미번역도
  원문과 대조해 별도 검수한 뒤 정확히 확인된 행만 변경합니다.
- 휴게소 `english_events_pitstop:4512`의 `...!`와 `:4797`의 `...?`도 문맥상 말없는
  반응이므로 번역은 `……`로 유지합니다. 검증 예외는 이 정확한 행·원문·번역 조합에만
  적용하며, 다른 유사 문자열에 자동 확장하지 않습니다.
- UI `RES_NEX`는 원문 `[0] of [1]`을 `[0] / [1]`로 표시하는 숫자 포맷 전용 항목입니다.
  이 정확한 ID·원문·번역 조합만 한글 없는 문자열 예외로 허용하며, 일반 문구에는
  예외를 확장하지 않습니다.
- UI 라디오 프리셋 `PSE_RAD_RADIONOISE`의 원문 값 `???`는 주변 프리셋 이름과 함께
  등장하는 원본의 의도적 표시 문자열입니다. `정체불명 라디오`처럼 의미를 덧붙이지 않고
  `???`를 그대로 유지하며, 검증 예외는 이 정확한 ID·원문·번역 조합에만 적용합니다.
- UI 원문 `GLR_VAR_ENDING_MVP_SLIME_CRYPTID_CONVENTION`은 키 이름 및 다른 `SLIME`
  엔딩 항목들과 달리 영문 표시명이 `MVP Ending Jacqueline - Cryptid Convention`으로
  추출되어 있습니다. 한국어는 현재 원문을 그대로 따라 `재클린`으로 번역했습니다.
  원문/카탈로그 자체의 불일치 가능성이 있으므로, 근거 없이 한국어만 `더그`로 바꾸거나
  원본·카탈로그를 수정하지 말고 upstream 의미가 확인될 때까지 보류합니다.
- `build_ui_preview.py`의 UI 메타텍스트는 3편 기본 로더가 직접 읽지 않지만,
  별도 BepInEx UI 브리지를 설치한 실게임에서 실제 로딩을 확인했습니다.

등으로 구분하고, 전체 시리즈의 고유명사 QA 때 장기 표기를 검토합니다.

## 로드트립 자원·시스템 용어 (게임 내 문맥)

| 원문 시스템 용어 | 통일 한국어 | 비고 |
| --- | --- | --- |
| STAMINA | 체력 | 자동차 여행의 공유 자원 |
| HYPE | 흥 | 게임 시스템 자원, '열기'와 혼용 금지 |
| MAGIC | 마력 | *자원값*을 의미하는 경우. 일반 마법 행위는 '마법' 허용 |
| MIND | 정신 | 게임 시스템 자원 |
| SOUL | 영혼 | 게임 시스템 자원 |
| MONEY | 돈 | 게임 시스템 자원 |
| PRANK DOLLARZ | 장난 달러 | 기존 휴게소 번역 표현 |
| PRANK TOKENS | 장난 토큰 | 메타 상점/가챠 보상 |
| HITCHHIKER | 히치하이커 | 동승자를 가리키는 명칭 |
| REST STOP | 휴게소 | 여행 중 정차 장소 |
| DEEP CONVERSATION | 깊은 대화 | 게임 시스템의 심화 대화 |
| PASSIVE EFFECT | 지속 효과 | 히치하이커/캐릭터 고유 효과 |

우선 적용 대상은 **실제 게임 UI의 능력치/자원명**입니다. 같은 영단어라도
문장 내 일반 의미(예: 무대의 열기, 마법 주문)를 가리키면 고정 번역을
기계적으로 강요하지 않습니다. 메타텍스트 `STA_HYPE`·`STA_MAGIC`은
이번 추가 UI 번역에서 각각 `흥`·`마력`으로 일치시켰습니다.

**스탯 효과 표현은 절대 원문을 치환하지 않습니다.** 설치본 `Assembly-CSharp.dll`의
`BeautifulGlitch.RegexUtils.GetRegexStatAny()` 및
`Game.MainGameEventManager.ProcessStatPatterns()` IL 검수 결과,
`+N2 STAMINA`, `-N2 SOUL`, `+N2 HYPE`처럼 부호·수치·대문자 영문 자원명이
연결된 표현은 실제 `StatType` 열거형을 파싱해 능력치 증감을 적용하는 게임 문법입니다.
이를 `+N2 체력`처럼 변경하면 정규식·열거형 해석이 실패하여 능력치 적용이
고장 날 수 있습니다. 이 패턴은 그대로 보존하고 주변 서술만 한국어로 번역합니다.
반면 자원 **UI 라벨**은 위 용어집대로 한글화합니다.
신규 번역에 대해 `verify_translation_delta.py`가 효과 토큰의 부호·N·수치·종류
일치 여부를 확인합니다. 기계적인 영문 스탯 단어 전역 치환은 금지합니다.

본 가이드는 초기안이며 기존 한국어판의 용어집과 일관성을 재검증해야 합니다.
